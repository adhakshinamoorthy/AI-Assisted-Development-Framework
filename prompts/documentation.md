# Documentation and requirements prompts

```text
Create implementation-faithful documentation for {{scope}} from supplied source evidence.
Include overview, audience, prerequisites, architecture, setup, usage, examples,
troubleshooting, security, limitations, and verification. Mark anything not proven by the
repository as unknown. Use plain English and runnable commands.
```

```text
Analyze {{requirement}}. Extract actors, goals, rules, constraints, edge cases, security
needs, non-functional requirements, acceptance criteria, unknowns, and a thin delivery plan.
Do not design around unstated assumptions.
```
